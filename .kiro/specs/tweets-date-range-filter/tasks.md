# 实现计划

- [x] 1. 实现辅助函数与端点参数扩展
- [x] 1.1 实现 UTC 时区确保辅助函数
  - 创建模块级私有函数，将 naive datetime 视为 UTC 并添加时区信息
  - 已有时区信息的 datetime 应保持不变直接返回
  - 参考 Feed API 中已有的 naive datetime 处理逻辑，保持一致性
  - _Requirements: 3.4_
  - _Contracts: _ensure_utc Service Interface_

- [x] 1.2 实现统一过滤条件构建辅助函数
  - 创建模块级私有函数，接收查询语句和过滤参数，返回追加了 WHERE 条件的查询语句
  - 按作者用户名精确匹配过滤（迁移现有内联逻辑）
  - 按创建时间起始边界过滤（含，`>=`），仅在参数非 None 时生效
  - 按创建时间截止边界过滤（不含，`<`），仅在参数非 None 时生效
  - 所有过滤条件以 AND 逻辑组合，仅追加 `.where()` 子句，不修改 SELECT/JOIN/ORDER BY
  - _Requirements: 1.3, 1.4, 1.5, 1.6, 2.1_
  - _Contracts: _apply_filters Service Interface_

- [x] 1.3 扩展推文列表端点，接收时间范围参数
  - 在端点函数签名中新增两个可选的 ISO 8601 datetime 查询参数，默认为 None
  - 对提供的时间参数调用 UTC 确保函数进行时区标准化
  - 当两个时间参数都提供时，校验起始时间必须早于截止时间，否则返回 HTTP 422 错误
  - 将数据查询和计数查询的过滤逻辑替换为统一的过滤辅助函数调用，确保两者条件一致
  - 不修改响应模型结构，保持现有排序方式和分页逻辑不变
  - 不提供时间参数时，行为与当前完全一致（向后兼容）
  - _Requirements: 1.1, 1.2, 2.2, 2.3, 2.4, 3.1, 3.2, 3.3, 4.1, 4.2, 4.3_
  - _Contracts: list_tweets API Contract_

- [x] 2. 测试覆盖

  - 可增加额外的测试推文以覆盖更丰富的场景（不同作者 + 不同时间）
  - 确保调整后现有的测试用例仍然通过（向后兼容）
  - _Requirements: 4.2_

- [x] 2.2 编写时间范围过滤测试

  - 验证仅提供截止时间时，只返回该时间之前（不含）的推文
  - 验证同时提供起始和截止时间时，只返回半开区间内的推文
  - 验证返回的 total 和 total_pages 反映过滤后的数量
