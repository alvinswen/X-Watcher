- [x] 4. 摘要任务执行服务
- [x] 4.1 提取 LLM Provider 构建逻辑为公共函数
  - 从现有摘要服务的 provider 初始化逻辑中提取构建函数
  - 函数读取环境配置并按优先级顺序实例化可用的 LLM provider 列表
  - 确保现有摘要服务继续正常工作（使用提取后的公共函数）
  - _Requirements: 4.8_

- [x] 4.2 实现摘要任务执行服务
  - 实现任务创建逻辑：验证主题存在且有关联账号，创建 pending 状态的任务记录
  - 创建成功后通过 asyncio.create_task 在后台启动执行，不阻塞 API 响应
  - 后台执行流程：更新状态为 running → 查询关联账号列表 → 查询时间范围内的推文（优先使用已有中文翻译）
  - 构建聚合提示词：按作者分组组织推文内容，自动填充上下文变量（账号数量、时间范围、推文数量）
  - 提供默认提示词模板（按话题/事件组织、提取关键观点、标注来源、综合多方观点、中文撰写）
  - 支持自定义提示词覆盖默认模板
  - Token 估算和上下文窗口管理：超出 80K token 上限时截断最旧推文
  - 调用 LLM 生成摘要，使用 failover 模式尝试多个 provider，获取全局信号量控制并发
  - 成功时保存摘要结果及元数据（provider、model、token 用量、成本、推文数、账号数），更新状态为 completed
  - 时间范围内无推文时标记 completed 并保存提示信息
  - LLM 全部失败时标记 failed 并记录错误信息
  - 根据截止时间和时间跨度计算推文查询起止范围
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8, 4.9, 5.1, 5.2, 5.3, 5.4_
